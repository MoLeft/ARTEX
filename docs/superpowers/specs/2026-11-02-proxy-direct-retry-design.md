# 全局代理连接失败时直连重试

日期：2026-11-02

## 目标与边界

用户可在“系统设置 → 全局代理”开启“代理连接失败时直连重试”。默认关闭。开启后，只有 ARTEX 能确认**请求尚未到达目标**、且连接上游代理失败时，才对同一请求直连重试一次；关闭时只让当前请求失败，任务继续处理其他工作。目标站点自身拒绝连接、被屏蔽、证书错误、HTTP 错误或代理报告目标不可达，都不触发直连。

此设置作用于 ARTEX 管理的目标流量：Bash 子进程、WebFetch、使用全局或记录代理的自定义 HTTP 工具、Chrome MCP、内置 Lightpanda，以及流量捕获代理。自定义 HTTP 工具明确指定的其他代理、LLM 代理、网络搜索代理、更新代理和用户自行配置的外部 MCP 属于独立链路，不受此开关控制。流量捕获开启时，直连重试成功的请求仍经记录代理并正常留痕；关闭时不采集目标流量。

## 方案选择

采用本地出口代理作为唯一的全局代理接入点。直接给每个客户端加重试无法覆盖任意 Bash 命令和浏览器。把现有 MITM 改为永远运行、按开关关闭拦截，虽然可复用监听器，却需要修改第三方代理库的连接与记录行为，并会扩大证书和捕获逻辑的回归面。

本地出口代理仅监听容器/主机回环地址，支持现有的 HTTP、HTTPS、SOCKS5 上游代理及其认证。它接收 ARTEX 管理的 HTTP 请求和 CONNECT 隧道，建立上游连接；只有可确定的上游 DNS/TCP/TLS、代理握手或认证失败，且尚未转发目标请求时，才允许直连重试。SOCKS5 的目标连接失败回复、HTTP 代理的目标错误、已建立隧道后的 EOF/超时、上游返回的普通 HTTP 状态均按目标请求失败处理。任何无法归因的错误都不回退。每个请求最多重试一次，沿用原请求的上下文与超时；直接请求也失败时，向调用方返回失败并记录脱敏的两次错误。

请求路径：

| 条件 | 路径 |
| --- | --- |
| 无全局代理，捕获关闭 | Agent → 目标 |
| 无全局代理，捕获开启 | Agent → 记录代理 → 目标 |
| 有全局代理，捕获关闭 | Agent → 本地出口代理 → 上游代理；符合条件时 → 目标 |
| 有全局代理，捕获开启 | Agent → 记录代理 → 本地出口代理 → 上游代理；符合条件时 → 目标 |

Chrome MCP 沿用现有代理参数同步，但地址改为上述入口。内置 Lightpanda 使用其 `--http-proxy` 参数；在初始化 Manager 后启动，使其获得本地出口地址。改变全局代理、直连重试或捕获模式时，更新 ARTEX 管理的客户端配置。内置 Lightpanda 如需换代理地址则重启，其当前浏览器会话会中断；设置页须提示这一影响。外部 MCP 由外部进程自行管理，不承诺覆盖。

## 设置与状态迁移

新增布尔设置 `proxy_direct_retry_on_connect_failure`，缺失时为 `false`。GET/PUT 设置接口、前端类型和全局代理卡片同步此值；开关旁明确说明“直连会暴露本机出口 IP”，且开关默认关闭。若未配置全局代理，开关值可保存但没有效果。修改开关即时作用于新请求，不中断已建立的隧道。

现有“全局代理异常”判定把目标侧 EOF 与两个公共 IP 回显站点的失败等同于代理失联，并整批暂停任务。新行为取消这条全局自动暂停链：代理错误只返回给当前请求；设置页移除不再生效的代理重连次数和间隔控件，保留旧数据库键供兼容。升级时仅对 `paused_by_proxy` 的历史任务执行一次现有带原因和排程校验的恢复；用户暂停、排程暂停、终止和删除的任务不得恢复。手动“测试代理”仍严格测试上游代理本身，不使用直连回退，以免掩盖代理故障。

SOCKS5 目标连接失败不能再进入当前第三方 MITM 的 SOCKS5 上游路径，因此本地出口代理承担 SOCKS5 拨号，并用回归测试覆盖失败路径中的空连接 panic。不得把代理凭据、完整目标 URL 或敏感响应写入新增日志；只记录脱敏的故障阶段、目标主机和出口方式。直连回退应有可检索的事件，方便确认源 IP 何时可能暴露。

## 验证与上线

离线测试使用本地目标和假代理，覆盖 HTTP/HTTPS/SOCKS5 上游连接或认证失败、目标被拒绝、目标超时、连接建立后中断、开关关闭、直连再次失败，以及非幂等请求不重复发送。分别验证捕获开启与关闭的路由和记录行为；验证 Chrome/Lightpanda 的代理配置、设置持久化、历史代理暂停任务的保护条件和“测试代理”不回退。上线后用受控测试目标在 Mac Mini 核查两种捕获模式与开关状态，确认正常任务不被整批暂停，并保留可回滚的旧镜像。

## 风险与限制

开启回退后，符合条件的请求会从本机出口直接访问目标，目标可见真实出口 IP。上游代理已经接收目标请求后的错误不重试，以避免重复提交 POST 等请求。内置 Lightpanda 改代理地址时会重启；外部 MCP 的网络请求无法由 ARTEX 强制接管。
